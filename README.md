# MMA RACE

公開、免登入的 MMA 2026 投票觀測平台。使用真正的 WebGL 3D 原創 Q 版人物、迷你競技場、分類排行榜和 SVG 歷史曲線呈現投票資料。繁體中文介面，支援手機、候選人搜尋、暫停動畫、減少動態效果、累計票數 / 官方得票率切換、1H / 6H / 24H / 7D 和歷史 CSV 匯出。

## 啟動

需要 Node.js 24 或更新版本；3D 使用鎖定版本的 Three.js，模組從本站提供，訪客不需連線第三方 CDN：

```sh
npm ci
npm start
```

開啟 `http://localhost:3000`。`npm test` 執行測試。

## 3D 應援競技場

- 每個藝人或團體都有原創 Q 版應援代表：立體臉部、髮型、制服、球鞋，以及耳機、王冠、貓耳、護目鏡等配件。這些不是成員本人的分身、官方吉祥物或官方應援色。
- `public/characters.js` 定義造型。以藝人名稱決定固定外觀；同一藝人跨藝人、歌曲與專輯分類會沿用同一造型。尚未特別設計的藝人會依名稱穩定產生配色及配件。
- `public/race3d.js` 使用程序化幾何模型建立場景，包含燈光、陰影、觀眾席及跑道。以髖、膝、肩、肘關節驅動跑步，並加入身體起伏、頭部擺動與飄帶。沒有外部角色模型或真人肖像資產。
- 角色位置依票數比例平滑移動；跑步週期與票數分離，不捏造增票速度。終點格紋只是視覺參考，不表示投票完成。
- 每組展示 5 位角色，用左右翻頁涵蓋全部候選人。點人物或角色卡切換特寫，按「全景鏡頭」返回。下方保留可閱讀的票數比例與完整排名。
- 支援 WebGL 2 的現代瀏覽器。3D 啟動失敗或繪圖連線中斷會顯示明確提示，其他資料功能仍正常。暫停動畫與系統減少動態效果偏好會停止人物動作及鏡頭過渡；切換分類或視角仍可用。場景離開可見區域或分頁進入背景時停止渲染。

可設定 `PORT`（預設 `3000`）、`HOST`（預設 `0.0.0.0`）、`DATA_DIR`（預設專案內 `data/`）。SQLite 資料存於 `DATA_DIR/votes.sqlite`。只執行一個收集實例，避免重複請求。首次啟動會立即抓取 API，之後以每次請求開始時間為基準，每 5 分鐘再次抓取，單次請求最多等待 20 秒。排程在伺服器端執行，不依賴有人開著網頁。網頁每 15 秒讀取伺服器快取，不會對每位訪客分別請求 Melon。

## 公開部署

### GitHub Pages + Actions（本儲存庫使用）

網站：`https://susan561234.github.io/mma-race/`

`.github/workflows/pages.yml` 在推送 `main`、手動執行或 `*/5 * * * *` 排程時運作。它驗證 API 資料，把真實快照與收集狀態保存到 `vote-data` 分支，建置純靜態網站，再透過 Pages artifact 發布。無需第三方主機、登入或額外 API 密鑰。

**GitHub Actions 排程是盡力執行，可能延遲甚至略過，無法保證每 5 分鐘更新。** 公開儲存庫 60 天沒有活動時，定時工作流程可能被 GitHub 自動停用。請定期檢查 Actions，必要時重新啟用並手動執行。網站不顯示虛假的倒數或收集中狀態，只顯示最後成功時間；瀏覽器根據當前時間判斷是否過期。排程和部署延遲時曲線保留缺口。

每次收集後先提交資料分支，再建置發布。每日原始樣本保存在 `vote-data/daily/YYYY-MM-DD.jsonl`，不自動刪除；網站發布近 7 天資料供查詢。原始資料與 Git 歷史隨時間增長，投票結束後應停用排程以避免無用的收集。不要刪除或覆寫 `vote-data`，否則會失去觀測紀錄。

抓取失敗時保留最後成功資料，發布明確錯誤，並將工作流程標為失敗；若從未成功則顯示使用者提供的快照，歷史仍為空。`main` 是程式碼，`vote-data` 只有公開票數與錯誤狀態，兩者分開保存。相同 workflow 的 concurrency 群組避免同時寫入資料；GitHub 可能合併待執行工作，而非保證補執行每個間隔。

重新部署或移轉時，啟用 Settings → Pages → Build and deployment → **GitHub Actions**。執行 Actions → Collect votes and deploy Pages → Run workflow。部署只需要此儲存庫的 `GITHUB_TOKEN`，收集工作具備 contents write 權限，發布工作具備 pages write 與 id-token write 權限。

本機建置靜態網站：

```sh
npm ci
npm run collect       # 必須能連上 Melon；失敗會寫入錯誤狀態並返回非零
npm run build:pages   # 產出 dist/，可由任何 HTTP 靜態伺服器預覽
```

可設定 `STATE_DIR`（預設 `vote-state/`）、`OUTPUT_DIR`（預設 `dist/`）。Three.js 程式及其授權檔會複製至靜態網站的 `vendor/`；所有網址為相對路徑，可在 `/mma-race/` 等子目錄運作。只有建置輸出會被發布，原始碼、測試與資料庫不在 Pages artifact 內。

### 常駐 Node.js / Docker（仍保留支援）

原始後端也可以獨立部署至可常駐的 Node.js / Docker 主機，掛載持久化磁碟，並透過主機商或反向代理提供 HTTPS。不要使用會在無訪客時休眠的方案，否則無法持續收集。這個模式使用 SQLite，與 Pages 資料分支各自獨立。

```sh
docker build -t mma-race .
docker run -d --name mma-race --restart unless-stopped \
  -p 3000:3000 -v mma-race-data:/app/data mma-race
```

`GET /healthz` 檢查服務是否正常運行，`collectorError` 顯示最近收集錯誤。它不表示上游 API 一定正常；監控資料新鮮度請同時檢查 `/api/dashboard` 的 `stale` 與 `capturedAt`。部署前確認主機能連線至 Melon API，並遵守來源網站的使用規範。本站只讀取公開資料，不提供投票功能，也不要求帳號密碼。

## 資料真實性

- 來源：`https://m2.melon.com/m6/mma/2026/vote/category.json?lang=ko&t=<當前秒數>`，每次更新使用新時間戳避免快取。
- 初始內附使用者貼上的 12 分類、105 候選項目之真實快照票數，不是模擬資料。快照沒有原始觀測時間，因此不會寫入歷史曲線，也不會標為即時資料。初始快照只附上第一分類的已提供頭像；其餘顯示文字頭像，首次成功抓取後使用 API 提供的圖片。
- API 未提供分類正式名稱；介面使用「藝人 / 專輯 / 歌曲投票」與 `V26002` 等代碼識別，不推測正式獎項名稱。
- 完整驗證一次 API 回傳後才以交易寫入 SQLite；不完整、異常狀態、重複 ID 或非法票數會拒絕儲存並顯示錯誤，保留最後成功的資料。
- 得票率原樣使用 API 的 `votePercent`；因四捨五入，合計可能不等於 100%。票數不強制單調遞增，保留官方修正。
- 歷史曲線只使用成功收集的樣本，不補造歷史。只有一筆資料時顯示單點；超過 7.5 分鐘的缺口不連線。停機、連線失敗期間無法補回。資料庫保留全部樣本，介面最多查詢近 7 天。
- 跑道距離相對於當前第一名，不是投票截止進度；跑步動畫只是視覺效果，並非每個動作代表新的一票。
- 備份請使用 SQLite 線上備份工具，或先停止服務後複製資料目錄（包含可能存在的 WAL / SHM 檔案）。刪除持久化磁碟會失去歷史紀錄。

## 介面 API

- `GET /api/dashboard`：分類、最新資料、來源、收集時間、錯誤和新鮮度。
- `GET /api/history?category=V26002&range=24h`：真實樣本；範圍支援 `1h`、`6h`、`24h`、`7d`。

本專案無登入及寫入型公共 API，所有訪客只能讀取資料。非 Melon / MMA 官方服務，投票排名不代表最終得獎結果。
